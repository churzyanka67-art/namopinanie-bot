# Запуск на Bothost

## Настройки платформы

1. Репозиторий: `https://github.com/churzyanka67-art/namopinanie-bot.git`.
2. Ветка: `main` после принятия исправления структуры проекта.
3. Тип приложения / библиотека: Python, **aiogram**, если платформа предлагает этот выбор.
4. Дополнительные настройки → включить **«Использовать собственный Dockerfile»**. Файл `Dockerfile` лежит в корне репозитория. Он устанавливает зависимости из `requirements.lock.txt` и проверяет импорт `aiogram` и приложения.
5. Главный файл: `main.py`. Команда запуска: `python main.py`. Не указывать `pillbot/main.py` и не запускать `check_reminder.py` как основной процесс.
6. В переменных окружения указать `BOT_TOKEN` (твой токен) и `TIMEZONE=Europe/Moscow`. Не добавлять токен в Git. Переменные окружения уже поддерживаются приложением, `.env` на сервере необязателен.
7. Сохранить настройки и выполнить **новую сборку/деплой**, а не только перезапуск старого контейнера.
8. В runtime-логах проверить `Scheduler started` и `Run polling`. Затем отправить `/start`, указать дату первого приёма и время.

Бот использует long polling. Ему не нужен HTTP-порт, домен или webhook. Не запускай одновременно копию с тем же токеном на компьютере.

## Почему сборка раньше падала

Сообщение `RUN python -c 'import telegram'` проверяет модуль библиотеки `python-telegram-bot`. Этот проект использует `aiogram`, поэтому `telegram` не импортируется и не нужен в зависимостях. Скриншот указывает на проверку в автоматически сгенерированной сборке; точная причина выбора шаблона без доступа к настройкам панели неизвестна. Кастомный Dockerfile заменяет автоматическую сборку и проверяет реальные зависимости проекта.

В загруженном репозитории также была потеряна структура каталогов: файлы пакета `pillbot/` оказались в корне, а внутренний `main.py` заменил стартовый. Такая копия падает с `ImportError: attempted relative import with no known parent package`. В корне должен лежать короткий стартовый `main.py`, а основной код — в папке `pillbot/`.

Не нужно добавлять `python-telegram-bot` только ради прохождения неправильной проверки: это не исправит структуру проекта.

## SQLite

В Docker приложение находится в `/app`, база автоматически создаётся в **`/app/data/bot.sqlite3`**. Bothost документирует `/app/data` как каталог для сохранения данных при обновлениях. Не хранить базу в Git.

Настройки, введённые ранее в локального бота, сами на сервер не переносятся. Либо заново пройди `/start`, либо при остановленных процессах перенеси базу и её WAL-файлы из локальной `data/` в `data/` через файловый менеджер Bothost. После переноса проверь доступ на запись к каталогу.

## Проверка без ожидания выбранного времени

При работающем основном процессе в терминале Bothost:

```bash
cd /app
python check_reminder.py
```

Перед этим заверши настройку через `/start`. Это настоящее напоминание за сегодня: повторно в выбранное время оно не придёт.

## Проверка Docker вне Bothost

```bash
docker build -t pillbot .
docker run --rm --env-file .env -v pillbot-data:/app/data pillbot
```

Не выполняй второй запуск, если экземпляр уже работает на Bothost. При локальной подготовке исправления Docker отсутствовал: проверены Python-импорты, синтаксис и тесты, но сборка образа должна быть подтверждена логами Bothost.

Официальная документация: [кастомный Dockerfile](https://bothost.ru/docs/custom-dockerfile), [точка входа](https://bothost.ru/docs/main-file-entrypoint), [переменные окружения](https://bothost.ru/docs/environment-variables), [хранение базы](https://bothost.ru/docs/database-storage).
