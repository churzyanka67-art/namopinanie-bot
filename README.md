# Telegram-бот для напоминания о таблетке

## Запуск на Bothost

Для Bothost используй [отдельную инструкцию](deploy/BOTHOST.md): включи собственный Dockerfile, укажи `main.py` и задай `BOT_TOKEN` в настройках платформы. При загрузке в GitHub сохраняй папки `pillbot/`, `tests/` и `deploy/`; не собирай их файлы в одну папку.

Python **3.11+**, aiogram **3.x**, APScheduler **3.x**, SQLite. Бот отправляет каждый день **в выбранное пользователем время по Москве**:

> 💊 Время выпить таблетку!
>
> [✅ Я выпила]

После нажатия приходит **отдельное новое сообщение** `Сегодня 5-й день, ты умничка! ✨`, а кнопка удаляется. Подтверждение сохраняется в SQLite; повторное нажатие не создаёт вторую похвалу. На следующий день — новое напоминание с новой активной кнопкой.

## Персональная настройка

После `/start` бот сначала спрашивает дату первого приёма в формате `ДД.ММ.ГГГГ`, затем время напоминания `ЧЧ:ММ` **по Москве**. Например: `01.10.2026`, затем `22:59`. Дата должна существовать и быть не позже сегодняшней; время — от `00:00` до `23:59`. Допускается `9:05`, оно сохраняется как `09:05`.

Номер дня считается по календарю: дата первого приёма — день №1. Например, 1 октября — первый день, 5 октября — пятый, даже при пропусках. Напоминания ежедневные, без циклов и перерывов. Число 5 в примерах ниже бот заменяет рассчитанным номером.

Для изменения даты или времени снова отправь `/start`. Старое расписание продолжает действовать до завершения новой настройки. Настройки и незавершённые вопросы сохраняются после перезапуска. Если выбранное время сегодня уже прошло, новое расписание начинается завтра. Если напоминание за сегодня уже было, смена времени не создаст второе.

**После обновления старой версии:** снова отправь `/start` и ответь на оба вопроса. Прежние регистрации и история остаются в SQLite, но до ввода даты первого приёма и времени ежедневные напоминания для старого профиля не включаются. Миграция выполняется автоматически при запуске; удалять базу не нужно.

Если подтвердить старое сообщение на следующий день, ответ явно укажет его дату: `За 25.10.2026 — 5-й день, ты умничка! ✨`. Изменение даты начала курса не меняет счётчик уже отправленных напоминаний. У сообщений из старой версии, для которых дата начала неизвестна, сохраняется прежняя похвала без номера дня.

## Быстрый запуск на macOS / Linux

В терминале, находясь в папке проекта:

```bash
python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# Впиши свой токен в .env перед запуском
python main.py
```

Версия Python должна быть не ниже 3.11. Перед первым запуском создай `.env` по инструкции ниже.

Для новой установки скопируй `.env.example` в `.env` и впиши свой токен:

```dotenv
BOT_TOKEN=your_telegram_bot_token
TIMEZONE=Europe/Moscow
```

Пробелы вокруг токена удаляются при чтении. `.env` загружается из папки проекта независимо от текущей рабочей папки. Уже установленные переменные окружения имеют приоритет. `.env` не должен попадать в Git или публичные архивы; он добавлен в `.gitignore`. Часовой пояс намеренно ограничен `Europe/Moscow` согласно заданию.

1. Запусти `python main.py`.
2. Открой своего бота в Telegram и отправь **`/start` в личном чате**.
3. Укажи дату первого приёма и удобное время по Москве. Дождись подтверждения настройки. Данные сохранены в `data/bot.sqlite3`.
4. Держи процесс запущенным. `Ctrl+C` останавливает бота.

Дополнительных Telegram-команд и меню нет. `/start` можно повторять: дубли регистрации не создаются. Каждый личный чат, завершивший настройку после `/start`, получает собственные напоминания; чужой пользователь подтвердить их не может. Группы не регистрируются.

## Проверка, не дожидаясь выбранного времени

Оставь `main.py` работающим, пройди оба вопроса после `/start`, затем **во втором терминале** из папки проекта выполни:

```bash
.venv/bin/python check_reminder.py
```

Скрипт отправит **настоящее сегодняшнее напоминание** всем настроенным чатам, используя ту же SQLite и ту же защиту от дублей. Он не запускает второй polling-процесс.

- Проверь текст напоминания и кнопку `✅ Я выпила`.
- Нажми кнопку: должно появиться отдельное сообщение `Сегодня 5-й день, ты умничка! ✨`, а кнопка исчезнуть.
- Повторно запусти скрипт: второго напоминания за сегодня не будет.
- Перезапусти `main.py` и снова запусти скрипт: дубля также не будет.

**После ручной отправки сегодня второго сообщения не будет.** Следующее придёт завтра в выбранное время. Скрипт позволяет проверить отправку немедленно, даже если новое расписание начинается завтра. Если за сегодня запись уже существует, скрипт ничего повторно не отправляет. Удалять рабочую базу ради проверки не нужно. Пока `main.py` выключен, скрипт может отправить напоминание, но нажатия обработаются только после запуска основного бота.

Автоматические проверки без Telegram и без токена:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q main.py check_reminder.py pillbot tests
.venv/bin/python -m pip check
```

Они проверяют настройку даты/времени, восстановление незавершённого диалога, персональные расписания, миграцию старой базы, календарный счётчик, сохранность SQLite, конкурирующие отправки, перезапуск, следующий день, чужой user_id/chat_id/message_id, повторные нажатия, сбои сети, ограничения частоты API, удаление клавиатуры и расписание на сервере с UTC.

## Круглосуточная работа на Linux-сервере: systemd

Нужен постоянно включённый сервер с интернетом и Python 3.11+. Сон ноутбука или закрытый терминал не обеспечивают круглосуточную работу. Системные часы сервера должны быть синхронизированы; его часовой пояс менять не нужно. Один токен — один процесс `main.py`.

Ниже пример установки в `/opt/pillbot` на Debian/Ubuntu с поддерживаемым Python. Сначала установи Python 3.11+ и модуль `venv`, если их нет. Загрузи файлы проекта на сервер в свою папку `~/pillbot`, **без локальных `.venv` и `__pycache__`**, а `.env` перенеси приватно. Затем на сервере:

```bash
sudo useradd --system --user-group --home-dir /opt/pillbot --shell /usr/sbin/nologin pillbot
sudo install -d -o pillbot -g pillbot /opt/pillbot
sudo cp -r ~/pillbot/. /opt/pillbot/
sudo install -d -o pillbot -g pillbot /opt/pillbot/data
sudo chown -R pillbot:pillbot /opt/pillbot
sudo chmod 600 /opt/pillbot/.env
sudo -u pillbot python3 -m venv /opt/pillbot/.venv
sudo -u pillbot /opt/pillbot/.venv/bin/python -m pip install -r /opt/pillbot/requirements.txt
sudo cp /opt/pillbot/deploy/pillbot.service /etc/systemd/system/pillbot.service
sudo systemctl daemon-reload
sudo systemctl enable --now pillbot
sudo systemctl status pillbot --no-pager
```

Если системный пользователь `pillbot` уже создан, пропусти `useradd`. Папка `/opt/pillbot/data` должна существовать до запуска службы: systemd разрешает запись только в неё.

Просмотр логов, перезапуск и остановка:

```bash
sudo journalctl -u pillbot -f
sudo systemctl restart pillbot
sudo systemctl stop pillbot
```

Служба запускается при загрузке сервера и перезапускает процесс при завершении. Токен читается из `/opt/pillbot/.env`; логирование маскирует строки, похожие на токены. Логи systemd показывают время в настройках сервера; само расписание всегда использует Москву.

Быстрая проверка на сервере после `/start` и завершения настройки:

```bash
sudo -u pillbot /opt/pillbot/.venv/bin/python /opt/pillbot/check_reminder.py
```

Перед переносом с компьютера на сервер останови локальный `main.py`. Чтобы сохранить регистрацию и дневные записи, перенеси **папку `data` целиком при остановленных процессах**. Не копируй только основной SQLite-файл во время работы: рядом могут быть WAL-файлы. Не запускай копии с независимыми базами и одним токеном — у них нет общей защиты от дублей.

## Надёжность и перезапуски

- APScheduler создаёт отдельное ежедневное задание для каждого настроенного чата с явно указанным `Europe/Moscow`, без случайной задержки. Время доставки на телефон зависит также от сети и Telegram.
- SQLite хранит получателей, персональные настройки, шаг диалога, дату напоминания, зафиксированную дату первого приёма, статус отправки, message_id и время подтверждения. Уникальность `(chat_id, day)` запрещает второе напоминание за ту же московскую дату, в том числе при одновременном запуске ручной проверки.
- Бронирование отправки фиксируется **до** обращения к Telegram. После перезапуска подтверждённые, отправленные и зарезервированные записи остаются в базе.
- При запуске бот восстанавливает персональные задания из SQLite. Если выбранное время сегодня уже прошло и расписание уже действует, он пытается отправить сегодняшнее пропущенное напоминание, только если записи за сегодня ещё нет. Старые дни не догоняются. Новая настройка на уже прошедшее сегодня время начинает действовать завтра; для немедленной проверки используй скрипт.
- Подтверждение проверяет user_id, chat_id и message_id. Оно записывается атомарно до сетевых вызовов. Если процесс упал после доставки, но до сохранения message_id, первое действительное нажатие владельца завершает привязку сообщения.
- Если Telegram не позволяет удалить кнопку, нажатие уже не сможет повторно подтвердить приём: состояние сохранено в базе.
- При явном ответе Telegram `RetryAfter` напоминание повторяется после указанной Telegram задержки, пока повтор ещё помещается в текущие московские сутки; ограничение в три попытки для напоминаний отсутствует. Вспомогательные ответы и удаление кнопки повторяются до трёх попыток. Ошибки отдельных отправок логируются и не останавливают работу с остальными чатами. Long polling автоматически восстанавливает соединение.

**Неизбежное ограничение:** Telegram `sendMessage` и SQLite не составляют общей транзакции. При аварийном завершении между бронированием и отправкой напоминание может быть пропущено. При сетевом тайм-ауте нельзя надёжно узнать, доставил ли Telegram сообщение. В этих случаях бот сохраняет запись и **не повторяет отправку автоматически**, чтобы выполнить требование об отсутствии дублей. Ошибки помечаются в логах как `Delivery uncertain` или `Reminder rejected`. Аналогично, если подтверждение уже сохранено, а отправить похвалу не удалось, приём останется подтверждённым без повторной похвалы. Это сознательный выбор в пользу отсутствия дублей; абсолютной гарантии доставки при сбоях сети нет.

Если бот заблокирован, Telegram отклонит отправку; разблокируй его и снова отправь `/start`. Неуспешное сегодняшнее напоминание автоматически не повторяется, завтра будет новая попытка. Если токен недействителен, запуск завершится с ошибкой. При настроенном webhook бот сообщает об этом и завершает работу: прежнюю интеграцию нужно остановить и удалить webhook, прежде чем переходить на polling.

## Файлы

```text
main.py                  запуск polling и планировщика
check_reminder.py        отправить сегодняшнее напоминание сейчас
pillbot/config.py        настройки .env и безопасные логи
pillbot/storage.py       SQLite и атомарная защита от дублей
pillbot/service.py       отправка и подтверждение приёма
pillbot/main.py          /start, callback и запуск
pillbot/setup.py         вопросы даты/времени и валидация
pillbot/scheduler.py     персональные задания APScheduler
requirements.txt         зависимости
requirements.lock.txt    точные версии проверенного окружения
.env.example             шаблон без секрета
.env                     личный токен; исключён из Git
deploy/pillbot.service   служба systemd
tests/test_bot.py        отправка, подтверждения и защита от дублей
tests/test_settings.py   настройка, миграция и личное расписание
data/                    рабочая SQLite; создаётся автоматически
```

Для воспроизводимой установки проверенных версий можно использовать `python -m pip install -r requirements.lock.txt` вместо `requirements.txt`.

Документация библиотек: [aiogram — long polling](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html), [aiogram — ошибки API](https://docs.aiogram.dev/en/latest/dispatcher/errors.html), [APScheduler 3 — CronTrigger](https://apscheduler.readthedocs.io/en/3.x/modules/triggers/cron.html).
